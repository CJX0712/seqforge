## 1. 用途（Intended Use）

SeqForge 是一个**序贯贝叶斯推断与状态空间估计的研究型实验台**，
用于在已知真值的合成状态空间模型上，可复现地比较：

- **滤波**：KF / EKF / IEKF / UKF（解析解族）
- **粒子滤波**：bootstrap SIR / Auxiliary PF（蒙特卡洛族）
- **平滑**：RTS（解析）/ FFBS（粒子）
- **边缘似然估计**：这是本域的核心指标（模型证据、模型选择的基础）

**适用场景**

| 场景 | 适用性 |
|------|--------|
| 教学/研究线性高斯状态空间模型 | ✅ 22 条不变量提供逐项可验证的参照 |
| 理解「提议分布如何影响粒子退化」 | ✅ APF vs SIR 的 ESS 对照是核心实验 |
| 稀疏/缺失观测下的滤波实现参考 | ✅ 统一的 `NaN` 口径 |
| 粒子法边缘似然的偏差量化 | ✅ 线性高斯域有 KF 精确值作金标准 |
| 生产级状态估计部署 | ⚠️ 仅参考；本库无重试/异常恢复/流式接口 |

**明确不适用**

- ❌ 不适合 GPU / 分布式 / 大规模（粒子数受 CPU 内存约束）
- ❌ 不适合作为「通用贝叶斯推断框架」（无 MCMC / 变分推断）
- ❌ 不适合非线性观测 + 强先验约束的工业场景（无约束处理）

## 2. 数据（Data）

**全部为合成数据**，无真实数据集、无外部数据依赖、无隐私风险。

| DGP | 状态维度 | 观测维度 | 结构 | 专门暴露 |
|-----|---------|---------|------|---------|
| `linear_gaussian` | 4 | 4 | 线性高斯，全秩 A，谱半径 0.82 | KF 精确最优 ⇒ 偏差金标准 |
| `nonlinear_obs` | 4 | 4 | 线性转移 + quadratic/radar/tanh 发射 | 一阶线性化失效 |
| `sparse_obs` | 30 | 7 | **全秩** A（谱半径 0.90）+ 30% 稀疏观测 | 维度驱动的粒子退化 |
| `degenerate` | 6 | 3 | 窄似然（r=0.05）/ 双峰（\|λ\|≈0.985） | 提议分布与重采样的边界 |

**合成参数**

- 转移矩阵 `A`：实对称、谱半径**精确可控**（`V diag(s) Vᵀ` 后归一）
- 过程噪声 `Q = σ_q² I`，观测噪声 `R = σ_r² I`（严格正定，保证 Cholesky 可用）
- 初始状态：真值 `x₀ ~ N(0, 1.2²)`；**方法侧统一用 `x̂₀ = 0, P₀ = I`**（显式约定）
- 稀疏观测：缺失维度记为 `NaN`，所有方法按「跳过该维更新」处理

**防泄漏硬约束**：`x_true` 只用于评估，**绝不进入任何方法的推断路径**。
`sparse_obs` 的 `_observed_idx` 显式记录可观测维度，避免用不可观测维度的
RMSE 掩盖真实差异。

## 3. 指标（Metrics）

| 指标 | 方向 | 语义 | 适用 |
|------|------|------|------|
| `log_lik` | 越大越好 | 对数边缘似然 | 全部 |
| `rmse_state` | 越小越好 | 全状态 RMSE | 全部（部分可观测时**不具区分度**） |
| `rmse_obs` | 越小越好 | 可观测子空间 RMSE | `sparse_obs` 才有意义 |
| `ess_mean` | 越大越好 | 有效样本量 | 仅粒子法 |
| `smoother_rmse` | 越小越好 | 平滑轨迹 RMSE | 支持平滑的方法 |

**为什么不用单一指标**：本域的「性能」在不同域下由不同机制决定 ——
线性域看偏差（O(1/N)），高维看 ESS，稀疏域看双 RMSE 口径。

## 4. 实测基线（3 seeds，真实运行输出）

### 4.1 主表

| 方法 | 族 | log_lik (mean ± std) | rmse | mean ESS |
|------|----|---------------------|------|----------|
| KF | kalman | −113.99 ± 222.67 | 0.2579 | — |
| APF | particle | −194.77 ± 144.86 | 0.2403 | 444.4 (44.4%) |
| bootstrap SIR | particle | −230.20 ± 112.53 | 0.2389 | 310.2 (31.0%) |

> 跨 4 个 DGP 聚合。注意 std 极大（222.67）源于不同 DGP 的 log-lik 量级差异
> 极大，**不代表方法不稳定**——分 DGP 的 std 在 0.2~2.1 量级。

### 4.2 核心确定性证据：ESS 对照

线性高斯域，N=1000，seed=7：

| 方法 | 提议分布 | mean ESS | 占比 |
|------|---------|----------|------|
| bootstrap SIR | 先验 `p(x\|x_prev)`（**不含观测**） | 305.7 | 30.6% |
| Auxiliary PF | 最优 `q ∝ p(y\|x)p(x\|x_prev)` | **612.8** | **61.3%** |

**ESS 提升 2.00×**，且这是**可复现的确定性量**，不依赖 seed 统计显著性。

### 4.3 偏差量化（线性高斯域，KF 为精确真值）

| N | bootstrap 偏差 | APF 偏差 |
|---|---------------|---------|
| 400 | −0.36 /step | — |
| 1000 | −0.348 /step | — |
| 3200 | −0.329 /step | — |

偏差随 N 单调收缩，符合 O(1/N) 理论。

## 5. 局限（Limitations）

### 5.1 结构性限制（本域的数学事实）

1. **主指标在主域上不可超越**。线性高斯下KF 是精确贝叶斯最优，
   粒子法只能以 O(1/N) 逼近。本库因此把 KF 精确值当作**偏差金标准**
   而非「待超越的基线」。
2. **性能门禁不能用统计量**。实测 `log_lik` 的 seed 间 std 可达 0.7~1.4，
   方法间差值仅 0.2~2.1，「均值差 > ½(σ₁+σ₂)」在 3~5 seeds 下随机翻转。
   门禁全部落在 22 条确定性不变量上。

### 5.2 实现局限

3. **稀疏观测域 APF 的 ESS 低于 SIR**（n=30: 4.3% vs 37.2%）。
   根因：可观测维度太少时最优提议退化为先验提议，而辅助重采样仍按 α
   损失多样性。这是**真实发现**，不是 bug。
4. **消融显示「关闭辅助重采样」略优**（偏差 −32.97 vs −35.07）。
   真正增益来自「最优提议」而非「辅助重采样」。负结果已保留。
5. **`statsmodels` 0.15 移除了 `initial_state`**，三种初值下 llf 与自研 KF
   差 −141~−59，无法对齐口径，故只作参照不作逐位基线。
6. **FFBS 的 `filter` 与 `smooth` 共用同一份前向粒子集**。
7. **UKF 无平滑器**：雅可比沿平滑路径需重算，本库不提供近似版本。

### 5.3 统计局限

8. **3 seeds 不足以支撑显著性结论**。库中`significance()` 按任务书口径
   实现（|Δ| > ½(σ₁+σ₂)），但其结果**仅进报告，不做门禁**。
9. **粒子法的 Monte-Carlo 误差未做严格量化**。跨版本/跨 BLAS 的
   数值稳定性靠 legacy `RandomState` + 版本锁保证，未做理论上界。

## 6. 伦理与使用边界（Ethics & Misuse）

- 全部数据为合成，**无隐私风险**
- 本库是**研究工具**，其性能结论仅限于本文列出的 DGP 与参数范围
- ⚠️ **不要**把合成数据上的结论直接外推到真实业务数据：
  真实系统的模型错设（model misspecification）会让"最优方法"变成"最差方法"
- ⚠️ 粒子滤波的 ESS 崩溃在生产中会静默产生错误的边缘似然，
  若用于模型选择，**必须**同时监控 ESS

## 7. 复现（Reproduction）

```bash
git clone https://github.com/CJX0712/seqforge.git && cd seqforge
python -m pip install -r requirements.lock.txt
python examples/run_demo.py --ablation       # 落盘 artifacts/benchmark.json
python -m pytest tests/test_invariants.py -v  # 22 条不变量
```

**确定性保证**：同 seed 两次运行，72 行 benchmark 数据逐位一致
（仅 `elapsed_sec` 不同）。

**环境**：Windows 11 / 无 GPU / Python 3.12~3.13 / numpy 2.5.3 / scipy 1.18.1
（CI 矩阵：ubuntu + windows × py3.12 + py3.13）
